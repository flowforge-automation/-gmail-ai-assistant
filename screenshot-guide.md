# Screenshot Checklist — Portfolio Visuals

Use these to make the case study and any landing page/profile more convincing. Aim for clean, uncluttered screenshots — crop out anything unrelated (other browser tabs, desktop icons, personal emails you don't want visible).

## Before you start
- [ ] Close/hide anything personal (unrelated emails, browser bookmarks, other apps)
- [ ] Use a real but non-sensitive example email for demos if possible (or blur senders' addresses you don't want public)

## Version 1: Python
- [ ] Terminal/cmd showing the script running successfully (the "Processing: ... Draft reply saved" output)
- [ ] A snippet of the code itself (e.g. the `classify_and_draft` function) — nice for showing you can read/write code
- [ ] The resulting Gmail draft it created

## Version 2: Cowork
- [ ] The Cowork chat where you gave the instruction ("Διάβασε τα emails μου...")
- [ ] The moment it shows it's using the Gmail connector / reading emails
- [ ] The Skills page (Customize > Skills) showing your saved "email-assistant" skill
- [ ] The resulting Gmail draft it created

## Version 3: Zapier
- [ ] The full Zap overview — all 3 steps visible in one view (Gmail trigger → Claude → Gmail draft)
- [ ] The "Send Message" (Claude) step configuration, showing the prompt
- [ ] The test result showing Claude's generated reply
- [ ] The Zap turned ON (published)
- [ ] The resulting Gmail draft it created

## Bonus (optional but strong)
- [ ] Side-by-side: the same email, replied to differently by each of the 3 versions — shows consistency across implementations
- [ ] A short screen recording (30-60 sec) of one version running live — even more convincing than static screenshots

## Where these go
- Case study document (case-study.md): 2-4 of the strongest ones
- Upwork/Fiverr portfolio: 3-6 images per project sample
- GitHub README: 1-2 screenshots max, keep it code-focused there
